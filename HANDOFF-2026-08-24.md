## 5. Gotchas that cost real time — the ones NOT already in the older handoffs

The existing list (heredoc `\\` collapse, per-file line endings, `flags = TRUE` belongs
to `summary()`, never wrap a suite in `suppressWarnings`) still applies. These are new:

- **roxygen `@md` silently drops a whole `@details` block.** A raw `\tabular` inside an
  `@md` block makes roxygen print `✖ ... has mismatched braces or quotes` and write the
  `.Rd` **without the entire `\details`** — while `check_man()` reports "No issues
  detected". Use a markdown table. Braces and quotes both balanced; four other
  hypotheses tested innocent before paragraph-level bisection found it. There is now a
  test asserting the block EXISTS, because that is the failure `check_man` cannot see.
- **`[text]` inside an `@md` block becomes a link.** `"95% CI [.85, .91]"` rendered as
  `\link{.85, .91}` — a dead cross-reference. Reword; do not bracket.
- **Line endings, from the other direction.** Reading the *working copy* under
  `core.autocrlf=true` gives CRLF, so an edit helper that detects "the file's
  convention" from it will rewrite an LF file to CRLF and can leave **lone CR** bytes,
  making git show the whole file as changed. Repair by DELETING `\r` bytes, not
  converting them to `\n` (converting adds blank lines). Verify with a byte count, not
  with `file` or `grep -c $'\r'` — both misled me here.
- **`info_used` must not vary by row.** `internal_generate_df.R:356` evaluates
  `if (grepl(..., unique(df_temp$info_used)))`; a row-varying value makes that
  condition length-2, a hard error in R >= 4.2. The reliability roadmap proposed
  exactly that for 1.2's provenance and it would have crashed any mixed pool.
- **`.positive_or_na()` on a COMPUTED standard error can break a documented boundary.**
  Raw `alpha = 1` legitimately yields `se = 0`; guarding it NA'd the row out of
  `summary()` entirely. Guard the reported input, not the computed output.
- **Substring traps in your own checks.** `grepl("nrep100", x)` matches `nrep1000`.
  A verification probe can be wrong in the reassuring direction.
- **Tier-1 vs Tier-2 `flag_options`.** Input-data options are read from `convert_df()`;
  passing them to `summary()` is now warned about (item 2.5), but the asymmetry is
  real and easy to trip over when writing tests.
- **Measure V36-style flag rates via `.validate_input_data()` directly.** Going through
  `convert_df()` + `summary()` made the same sweep exceed a 10-minute budget; Tier-1
  is where the check lives and the effect-size machinery is irrelevant to it.
